## 1. 의도

가입 장벽을 없앤 뒤(#121) 남은 문제는 "들어와서 해 보면 어색하다"이다. 사용자 피드백을 그대로 옮기면:

- 선택지에 ▶ 세모와 "누르면 안 될 것 같은" 표시가 있고, 이야기를 넘기는 것과 고르는 것이 섞여 이상하다
- UI가 오래돼 보이고, 이상한 UI/UX는 다 바꿔야 한다
- 캐릭터가 장면마다 달라 보인다. 여러 표정·포즈가 일관되게 나와야 한다
- 엔딩이 별로고, 이야기가 더 짜임새 있어야 한다
- 전체적으로 리팩터링하면서 성능도 개선한다
- 그림은 Codex(구독 계정)로 가이드라인을 주고 다시 만든다. 표지(홈)는 그대로 둔다

성공 기준: 처음 온 사람이 설명 없이 끝까지 플레이하고, 다른 엔딩을 보려고 한 번 더 해 보고 싶어진다.

## 2. 범위

**목표**

- 대사 진행과 선택을 명확히 분리한 플레이 화면 (#127)
- 등장인물 설정과 대사 구조를 정리한 스토리 데이터, 개선된 엔딩 (#128)
- 캐릭터 시트 기반으로 일관된 인게임 그림 일체 (#129)
- 공용 컴포넌트와 의미 토큰만으로 그리는 모던 UI (#130)
- 화면 단위 코드 분할, 장면 미리 받기, 레거시 데이터 제거 (#131)

**하지 않는 것**

- 표지(홈 배경, 홈 캐릭터)는 바꾸지 않는다 (사용자 지시)
- 게스트 시작, 랭킹, 프로필의 API 계약은 바꾸지 않는다
- 새 게임 시스템(호감도 게이지 노출, 세이브 슬롯 등)은 추가하지 않는다 (제 판단)

**실패로 보는 것**

- 선택지가 정답 힌트를 주는 상태가 남는 것
- 같은 캐릭터가 장면마다 다른 사람처럼 보이는 것
- 모바일에서 대사창이나 선택지가 잘리는 것

## 3. 대사·선택지 UX (#127)

현재 문제(코드 조사로 확인):

| 문제                   | 원인                                                                        |
| ---------------------- | --------------------------------------------------------------------------- |
| 넘기기와 고르기가 섞임 | 선택 뒤 이어지는 대사(`subtext`)를 선택지와 같은 ▶ 버튼으로 하나씩 보여 줌 |
| 정답 힌트              | 게임오버 선택지에 ⚠와 빨간 테두리, 고득점 선택지에 금색 테두리             |
| 이름표 미사용          | 화자 이름이 본문에 섞여 있음 ("이수정 : …")                                 |

설계:

- **대사**: 화면 어디든 탭(또는 Space/Enter)하면 다음 줄. 타이핑 중 탭하면 그 줄을 즉시 완성. 대사창 위에 화자 이름표, 나레이션은 이름표 없이 기울임
- **선택지**: 그 장면의 대사가 모두 끝난 뒤에만 나타난다. 모든 선택지는 **같은 모양의 카드**이고 아이콘, 색, 테두리로 결과를 암시하지 않는다. 키보드 1~4로도 고를 수 있다
- **보조 조작**(제 판단): 자동 진행, 건너뛰기(이미 본 장면만), 지난 대사 보기(로그)
- 선택 뒤 이어지는 대사는 일반 대사와 똑같이 탭으로 넘긴다

## 4. 스토리·캐릭터·엔딩 (#128)

**등장인물 표** (이름은 제 판단 초안, 승인 시 확정):

| ID         | 표시 이름              | 역할                                                                     |
| ---------- | ---------------------- | ------------------------------------------------------------------------ |
| `player`   | 플레이어 닉네임        | 주인공. 회귀하는 연인. "주인공" 문자열 치환 방식을 없애고 화자 ID로 표기 |
| `sujung`   | 이수정 (호칭 "수정")   | 히로인. 본문 표기를 "수정"으로 통일                                      |
| `stranger` | ??? → 후반에 이름 공개 | 회귀를 일으키는 존재                                                     |

**데이터 구조**: 레거시 `data.jsx`~`data5.jsx`와 `intro.json`을 하나의 JSON 형식으로 통합한다.

```
scene: { id, background, characters: [{ id, expression, position }], lines: [{ speaker, text }],
         choices: [{ text, score, next, gameOver }] }
```

분기 규칙은 기존 `stageRules.json`과 `storyFlow.js`를 그대로 쓴다(회귀 테스트 25개 유지).

**엔딩**(제 판단 방향): 4종(해피, 미들, 새드, 히든)을 유지하되 각각 전용 장면 3~5개, 엔딩 일러스트 1장, 마지막에 "이번 회차에 고른 선택" 요약과 회귀 횟수를 보여 준다. 해피는 회귀의 끝, 새드는 다음 회귀로 이어지는 복선, 히든은 낯선 존재의 정체가 드러나는 구성. 점수 임계치는 스토리를 다시 짠 뒤 플레이 경로별로 다시 맞춘다.

## 5. 에셋 (#129)

- 도구: Codex CLI, **로그인된 구독 계정만** 사용 (API 키 사용 금지, 사용자 지시)
- 순서: ① 화풍 가이드 문서 고정 → ② 캐릭터 시트 3인(정면, 의상, 머리 고정) → ③ 시트를 참조로 표정 6종(기본, 웃음, 슬픔, 놀람, 화남, 울음) × 필요한 의상 → ④ 장소별 배경(집, 카페, 동굴, 우산 길, 해변, 엔딩 4종)
- 화풍: 기존 표지와 같은 수채화와 잉크 윤곽, 따뜻한 노을빛과 청록 대비, 배경은 아래 1/3을 대사창 자리로 비움
- 캐릭터는 투명 배경 PNG로 받아 webp로 변환(기존 webp·알파 규칙 테스트 그대로 적용)
- 시험 결과: 카페 배경 1장으로 화풍 일치와 품질을 확인함
- 생성물은 사람이 보고 고른 것만 반영한다 (제 판단: 장소별로 2안씩 받아 비교)

## 6. 모던 UI와 디자인 토큰 (#130)

- 공용 컴포넌트: 버튼, 카드, 모달, 이름표, 대사창, 선택지 카드, 아이콘 버튼
- 화면은 이 컴포넌트와 `semantic.js` 의미 토큰만 조합. `Home.styled.js`(810줄), `Board.styled.js`(552줄)의 하드코딩 값을 토큰으로 옮긴다
- 규칙 테스트: 화면 코드의 `rgba(`, `#hex`, 숫자 px 직접 사용 금지. 기존 위반은 파일별 개수로 고정하고 줄이기만 한다
- 확인: 데스크톱 1440×900, 태블릿 768×1024, 모바일 390×844에서 전 화면 캡처
- 시안은 구현 전에 `/pro-ui-design`으로 보여 주고 고른다 (사용자 규칙)
