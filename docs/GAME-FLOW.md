# 게임 진행 구조

> **이 문서의 목적**: 현재 동작을 정확히 기록한다. Phase 4에서 스토리 분기를 데이터화할 때
> **회귀 테스트의 기대값 근거**가 되는 문서다. 여기 적힌 대로 동작하지 않으면 마이그레이션이
> 잘못된 것이다.

## 전체 흐름

```
Home(/) ─ 닉네임·MBTI 입력 ─→ Intro(/intro) ─→ 스테이지 1(집, /main1)
                                        │
                                  스테이지 2(카페, /main2)
                                        │
                          ┌─────────────┴─────────────┐
                  "돈을 줍는다"                "카운터에 준다" / "그냥 간다"
                          │                             │
                스테이지 4(우산)                스테이지 3(동굴)
                          └─────────────┬─────────────┘
                                        │
                                스테이지 5(해변)
                                        │
                                  Result(/result)
                                        │
                       ┌────────────────┼────────────────┐
                    Happy            Middle             Sad
```

게임오버(`/over`)는 `error` 플래그가 붙은 선택지를 고르면 발생한다. 선택 뒤 이어지는 대사를 모두 본 다음 이동한다.

## 스테이지 구성

모든 스테이지는 `src/pages/StagePage.jsx` 하나가 그리고, 장소별 설정은 `src/game/stages.js`의
`STAGE_CONFIGS`가 단일 원본이다.

| 스테이지 | 장소 | 경로     | 스토리 데이터         | BGM             | 분위기 효과 |
| -------- | ---- | -------- | --------------------- | --------------- | ----------- |
| 1        | 집   | `/main1` | `src/utils/data.jsx`  | `/audio/1.m4a`  | `dust`      |
| 2        | 카페 | `/main2` | `src/utils/data2.jsx` | `/audio/2.m4a`  | `petals`    |
| 3        | 동굴 | `/main3` | `src/utils/data3.jsx` | `/audio/34.m4a` | `rain`      |
| 4        | 우산 | `/main4` | `src/utils/data4.jsx` | `/audio/34.m4a` | `rain`      |
| 5        | 해변 | `/main5` | `src/utils/data5.jsx` | `/audio/5.m4a`  | `sparkle`   |

스토리 데이터는 `toStageScript`가 장면·줄 단위 스크립트로 변환해 `DialoguePlayer`
(`src/components/scene/`)에 넘긴다. 마지막 장면이 끝나면 `다음 장소로` 버튼이 나타난다.

인트로는 `src/data/stories/intro.json`을 `fromIntroStory`로 변환해 같은 `DialoguePlayer`를
**자동 재생 모드**로 재생한다. 끝나거나 `인트로 건너뛰기`를 누르면 새 게임을 시작한다.

### 대사 진행 규칙

| 항목          | 동작                                                                              |
| ------------- | --------------------------------------------------------------------------------- |
| 진행          | 탭·Space·Enter. 타이핑 중 탭은 즉시 완성                                          |
| 선택          | 대사를 모두 본 뒤에만 선택지 표시. 모두 같은 모양, 키보드 1~4로 선택              |
| 이어지는 대사 | 선택 뒤 대사는 선택지 카드가 아니라 대사창에서 탭으로 진행                        |
| 자동          | 타이핑 완료 후 지연 뒤 진행. 직접 탭하면 수동으로 복귀                            |
| 건너뛰기      | 이미 본 줄만 빠르게 넘기고, 처음 보는 줄·선택지에서 멈춤 (본 줄은 sessionStorage) |
| 지난 대사     | 본 줄과 `선택 ·` 항목 목록 모달. 열려 있는 동안 진행 키 무시                      |

## 핵심 분기: 카페의 돈 줍기

스테이지 2(카페)의 마지막 씬 "바닥에 돈이 떨어져 있는 것을 발견했다"에서 다음 스테이지가 갈린다.

| 선택지          | 인덱스 | 다음 스테이지     | 스토리 연결                                    |
| --------------- | ------ | ----------------- | ---------------------------------------------- |
| "줍는다"        | 0      | 스테이지 4 (우산) | "얻은 돈으로 편의점에서 우산을 사올 수 있었다" |
| "카운터에 준다" | 1      | 스테이지 3 (동굴) | 우산이 없어 비를 피해 동굴로 들어간다          |
| "그냥 간다"     | 2      | 스테이지 3 (동굴) | 동일                                           |

`data3`(동굴)과 `data4`(우산)는 **둘 다 "갑자기 비가 온다"로 시작해 "해변으로 이동"으로
끝나는 대안 씬**이다. 순차 진행이 아니다.

## 점수 임계치

**`src/data/stageRules.json`이 단일 출처다.** `src/game/storyFlow.js`는 이 규칙을 평가만 한다.
아래 표는 그 데이터의 내용이며, `src/game/storyFlow.test.js`가 그대로 검증한다.

```json
"0": [
  { "when": { "scoreMin": 15, "scoreMax": 40 }, "to": 1 },
  { "when": { "scoreMax": 15 }, "to": 2 },
  { "to": 3 }
]
```

규칙 배열을 위에서부터 평가해 첫 번째로 조건을 만족하는 대상으로 이동한다.
`when`이 없는 규칙은 기본값 역할을 한다.

| 스테이지 | 조건                    | 분기                                                          |
| -------- | ----------------------- | ------------------------------------------------------------- |
| 2 (카페) | 씬 인덱스 0 종료 시     | `15 ≤ score < 40` → 씬 1 / `score < 15` → 씬 2 / 그 외 → 씬 3 |
| 2 (카페) | 씬 인덱스 1 또는 2 종료 | → 씬 3                                                        |
| 3 (동굴) | 씬 인덱스 1 종료 시     | `score ≥ 60` → 씬 2 / `20 ≤ score < 60` → 씬 3 / 그 외 → 씬 4 |
| 3 (동굴) | 씬 인덱스 2·3·4 종료    | → 씬 5                                                        |
| 4 (우산) | 씬 인덱스 2 종료 시     | `score ≥ 70` → 씬 3(맥주 특수 씬) / 그 외 → 스테이지 종료     |
| 5 (해변) | 씬 인덱스 2 종료 시     | → `/result`로 이동                                            |

씬 인덱스가 `plot.length`에 도달하면 "다음 스테이지로" 버튼이 나타난다.

## 게임오버

선택지에 `error` 필드가 있으면 게임오버 선택이다(`gameOver`로 변환). 점수는 반영하지 않고,
그 선택 뒤에 이어지는 대사를 대사창에서 모두 본 뒤 `/over`로 이동한다. 현재 4곳:

- `data.jsx` 스테이지 1 — 알람 "No" (약속에 늦어 시간이 되돌아감)
- `data3.jsx` 씬 6 — "소리를 무시하고 계속 이동한다" (동굴 붕괴)
- `data4.jsx` 씬 3 — "이수정 앞에 서서 뱀으로부터 막아준다" (뱀에 물림)
- `data5.jsx` 씬 3 — "그냥 같이 간다" (파도에 휩쓸림)

## 엔딩 분기

`src/pages/Result.jsx`의 "결과확인" 버튼이 `/api/game/over`로 결과를 전송한 뒤,
**클라이언트가 보유한 점수로** 엔딩을 결정한다. 서버 응답값은 분기에 쓰이지 않는다.

| 점수 조건           | 엔딩      |
| ------------------- | --------- |
| `score >= 100`      | `/happy`  |
| `50 <= score < 100` | `/middle` |
| `score < 50`        | `/sad`    |

`/hidden`은 이 분기에 포함되지 않는 별도 조건의 히든 엔딩이다.

> **주의**: 점수 전송이 실패해도(`catch`) 엔딩 이동은 그대로 진행된다. 서버에 기록이
> 남지 않은 채 엔딩만 보게 될 수 있다.

## 알려진 결함 (Phase 4에서 해소)

이 절의 내용은 `docs/superpowers/specs/2026-07-27-codebase-standardization-design.md` 1.2절의
진단과 대응한다.

### 1. 컴포넌트가 스토리 구조를 알고 있다 — **해소됨**

씬 전이 규칙이 `scene`/`index` 숫자 조건문 약 60줄로 컴포넌트에 박혀 있었다.

**해소 방식**

1. `src/game/storyFlow.js`로 순수 함수 추출 (컴포넌트의 `scene ===` 조건문 0건)
2. `src/game/storyFlow.test.js`에 전 경로 회귀 테스트 25개 — **현재 동작의 기대값 표**
3. 규칙을 `src/data/stageRules.json`으로 이관. 위 테스트가 데이터화 전후 모두 통과함을 확인

이제 **씬을 추가하거나 점수 임계치를 바꾸려면 JSON만 고치면 된다.** 코드는 손대지 않는다.

### 2. 우연히 동작하는 분기

`onClicked()`의 다음 코드는 씬을 구분하지 않고 **스테이지 2의 모든 씬**의 선택지 인덱스에
반응한다.

```js
if (scene === 2) {
  if (i === 0) setBase("/main4");
  else setBase("/main3");
}
```

씬 1에서 "카페 라떼"(인덱스 0)를 골라도 목적지가 `/main4`가 된다. 판단 근거가 되어야 할
"돈 줍기" 씬이 스테이지 2의 **마지막 씬이라 마지막 선택이 이겨서** 결과적으로만 올바르게
동작한다. 중간에 씬을 추가하거나 순서를 바꾸면 즉시 깨진다.

### 3. 읽히지 않는 데이터 필드

`data4.jsx`의 4번째 씬에 `love: 60`이 선언되어 있으나 컴포넌트는 이 필드를 읽지 않고
`score >= 70`으로 하드코딩한다. **선언값(60)과 실제 동작(70)이 다르다.**

> Phase 4 마이그레이션 시 **회귀를 막기 위해 실제 동작인 70을 유지**한다. 어느 쪽이 원래
> 의도였는지는 확인이 필요하다.

### 4. 거짓 prop — **해소됨**

스테이지 5(해변)의 `defaultExit`는 `null`이며 `resolveAfterScene`이 `/result`로 이동시킨다.
`/happy`로 가는 경로는 없다.

### 5. 잘못된 에러 메시지

`src/pages/Result.jsx`의 게임 결과 전송 실패 시 **"중복된 이메일입니다"** 알림이 뜬다.
회원가입 쪽 에러 메시지가 복사되어 남은 것으로 보인다. 게임 결과 전송과 무관한 문구이며
사용자를 혼란시킨다.

## 진행 상태 관리

`src/game/progress.js`가 진행 상태를 `sessionStorage`에 보존한다. 탭을 닫으면 초기화되므로
다음 방문 시 이전 판의 점수가 남지 않는다.

| 저장 항목          | 키                     | 용도                                        |
| ------------------ | ---------------------- | ------------------------------------------- |
| 점수               | `bagel:game:score`     | `scoreAtom`과 동기화. 새로고침해도 유지된다 |
| 최대 도달 스테이지 | `bagel:game:maxStage`  | 진행도 가드의 기준                          |
| 완료 여부          | `bagel:game:completed` | 결과·엔딩 화면 진입 자격                    |

### 진행도 가드

`src/components/RequireProgress.jsx`가 화면별로 접근을 제어한다.

| 화면                | 조건                                                     |
| ------------------- | -------------------------------------------------------- |
| `/main{N}`          | 직전 스테이지까지 도달했어야 한다                        |
| `/result`, 엔딩 4종 | 게임을 완료했어야 한다                                   |
| `/over`             | 게임을 시작했어야 한다 (게임오버는 플레이 도중 발생한다) |

조건에 미달하면 `/intro`로 안내한다.

> 클라이언트 가드이므로 우회 자체를 막지는 못한다. 목적은 보안이 아니라 **정상적으로
> 플레이하는 사용자가 새로고침·뒤로가기로 깨진 상태에 빠지지 않게** 하는 것이다.
> 점수 위변조 방지는 서버 검증 영역이다.

### 새 게임 시작

인트로에서 스테이지로 넘어가는 시점(`/intro`에서 스킵 또는 연출 완료)에 진행 상태를
초기화한다. 인트로 화면을 열기만 해서는 초기화되지 않는다.
